Split, fix, verify. Live.

A small bundled Python invoicing library has six bugs in six files: rounding, month arithmetic, pagination, accented names, a sort order and a shared default. That is 22 failing pytest tests, plus 21 passing tests that must stay green. Both modes run the same agent loop at the same time: same model, gemini-3.8-flash (thinking: low), same tools (list files, read a file, run tests, edit, finish), one action per turn. Each turn re-sends the conversation so far. Only the harness differs.

A branch sees only its group's failures, may edit only its own file, and its tests are the only ones it can run. Then merge, run the full suite, and retry a still-red group once with a fresh agent.

      What is being measured

      Tokens come from Gemini's usageMetadata on every call. Dollars use Google's published gemini-3.8-flash prices: $0.75 per million input tokens, $3.75 per million output tokens (thinking included), $0.075 per million cached tokens. When Gemini's implicit cache serves part of a prompt, those tokens are charged at the cached price, which helps the long conversation most. Time is wall-clock from the first pytest run to the final verdict.

      The small bars under each agent are its turns: bar height is the prompt tokens sent that turn, the lighter part is what the cache served. Every agent starts with the files in its scope (the whole project for the single agent, its own file and test file for a branch); tool output is cut at 4,000 characters; each mode stops calling the model once it has spent $0.25.

      Tests run in a throwaway copy of the bundled project with a timeout; agents can only read and write inside it, tests are read-only, and nothing you type is executed. This demo is deliberately simple and generic; the benchmark results on the results page come from Duelz's full engine.

      Built for the Google Cloud AI Builder Cup 2026. Runs on Cloud Run with Gemini; live-run results are stored in Firestore. One live run per visitor per minute.
